# 07 — GUI 界面框架设计（Wails，媒体预览 + 大数据流畅性）

> 本文件定义工具的**界面结构与交互逻辑**。硬性要求：
> ① 工作区具备**快速预览媒体内容**能力（图片/视频/表情/语音）；
> ② 面对大规模数据（单账号 14 万+ 文件）**绝不允许卡死**。
> 技术基础见 `04_tool_design.md`（Wails v2 + Go 后端）。

---

## 1. 设计原则（流畅性第一）

**三条铁律**：
1. **前端永不持有文件内容**——只持有轻量元数据（行引用/原因标签/大小），文件内容按需拉取
2. **UI 线程零文件 I/O**——所有扫描/读取/删除在 Go goroutine，通过事件回 UI
3. **渲染只做可见区**——任何列表必须虚拟化，绝不一次性建 14 万行 DOM

**分层的取舍**：
- 后端（Go）持有完整索引（内存 map：14 万条元数据，毫秒级查询）
- 前端（WebView）持有当前视图（一页 + 可视区行 + 已加载缩略图）
- 数据单向流：`Scan → 索引 → 查询(分页/筛选) → 渲染`

## 2. 整体布局（功能区划分）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 顶栏：数据根 ▾ │ 账号选择 ▾(QQ号) │ [扫描] [停止] │ 进度条(节流)   │
├──────────┬───────────────────────────────────────┬───────────────────┤
│ ② 左栏    │ ③ 中栏（文件浏览工作区 ★）              │ ④ 右栏（预览面板）│
│ 类型树    │  虚拟化表格：                           │  ★媒体预览 ★      │
│ Pic       │  [☑] 缩略图│名称│类型│大小│时间│说明   │   图片/视频/表情   │
│  Video   │   （仅渲染可视区 ~50 行）               │   缩略图秒开      │
│  Ptt     │  筛选/排序/月份折叠                     │   原图按需切换    │
│  Emoji   │  勾选列 → 实时累计                      │   详情/路径/说明  │
│  File    │                                        │                  │
│ 月份 ▾    │                                        │                  │
├──────────┴───────────────────────────────────────┴───────────────────┤
│ ⑤ 底栏：当前筛选文件数/大小 │ 可释放总量 │ [清理] │
└──────────────────────────────────────────────────────────────────────┘
```

**启发式指引**：浏览/清理应支持**按"缩略图维度"组织**（跨 biz 查看全部 Thumb）与按 biz 组织**平级**切换；
具体交互设计由开发者定（现象依据：Thumb 可重建、占缓存大头）。

## 3. 主流程（交互逻辑）

```
启动
 └─ 自动探测数据根（多平台候选，可改）→ 列出账号（QQ 号标注，见 02）
     └─ 选账号 + 选类型（默认 Pic/Video/Emoji）
         └─ [扫描] → 后端 goroutine 扫描 + EventsEmit 进度（≥100ms 节流）
             └─ 完成后：索引就绪 → 中栏分页加载第 1 页 → 状态=ready
                 ├─ 浏览：筛选/排序/翻页（虚拟化滚动，始终 60fps）
                 ├─ 预览：点选行 → 右栏立即显示（缩略图 <100ms，原图按需）
                 ├─ 勾选：行勾选 → 底栏"可释放总量"实时累加
                 └─ [清理]（有勾选才可点）→ MessageDialog 二次确认
                     → clean 包执行（进程保护/白名单/备份/审计日志）→ 状态=done
```

**状态机**：`idle → scanning → ready → cleaning → done`（+ `error`）
- scanning 中禁点 [清理]、可点 [停止]（取消扫描，保留已扫部分）
- ready 后可任意浏览/预览/勾选，**浏览与预览互不阻塞**（独立通道）

## 4. ★ 媒体预览设计（硬性要求）

### 4.1 预览数据通道（本地文件 → WebView）

Wails 前端无法直接访问本地任意路径，用 **`AssetsHandler`** 提供预览端点：

```go
// main.go
wails.Run(&options.App{
    Assets:       assetFS,           // embed.FS 前端资源
    AssetsHandler: previewHandler,   // 自定义：/preview/... 映射到本地文件
    Bind: []interface{}{backend},
})
```

```go
// previewHandler: 校验 → ServeFile（只读，白名单路径）
func previewHandler(rw http.ResponseWriter, req *http.Request) {
    p, ok := resolvePreviewPath(req.URL.Path)   // /preview/{biz}/{md5}.{ext}
    if !ok || !whitelisted(p) { http.NotFound(rw, req); return } // 防目录穿越
    http.ServeFile(rw, req, p)
}
```
- 前端用**原生标签**加载，零 JS 解码开销：
  - 图片 `<img src="/preview/Pic/Thumb/xxx_720.jpg">`
  - 视频 `<video src="/preview/Video/Ori/xxx.mp4" preload="metadata">`
- **白名单校验在 handler 内**：只允许 `nt_data` 富媒体目录内文件，拒绝 `..`/绝对路径（安全红线）

### 4.2 预览策略（按类型分策略）

| 类型 | 策略 | 预期耗时 |
|---|---|---|
| 图片·缩略图（Thumb） | 直接显示（`_720` 等 <100KB） | <50ms |
| 图片·原图（Ori） | **优先显示同 md5 的 Thumb**；无则加载 Ori（>50MB 提示不自动加载） | <100ms / 按需 |
| 视频 | `<video preload="metadata">` 只拉头部；封面用同目录 Thumb；点击才加载数据 | <200ms 出封面 |
| GIF/表情 | 直接显示（小文件） | <50ms |
| 语音（Ptt） | 元数据卡片 + 播放按钮（`<audio preload="metadata">`） | 即时 |
| 文件（File） | 元数据卡片（不预览内容） | 即时 |

- **同名 md5 关联**：Ori 与 Thumb 共享 `{md5}`，后端索引预计算 `md5 → {hasThumb, thumbPath, oriPath}`，前端请求直接拿缩略图路径

### 4.3 流畅性保障（绝不允许卡死）

| # | 机制 | 实现要点 |
|---|---|---|
| 1 | **虚拟化列表** | 中栏只渲染可视区（~50 行）+ 上下缓冲；滚动用 `requestAnimationFrame` 合并 |
| 2 | **懒加载缩略图** | `IntersectionObserver`：缩略图进入视口才请求 `<img src>` |
| 3 | **缩略图缓存** | 内存 LRU（约 500 项，`Map`+计数）+ 可选磁盘缓存目录 |
| 4 | **并发限制** | 预览/缩略图请求并发 ≤ 4~8，防打满磁盘 I/O |
| 5 | **请求去重** | 同一 URL 并发多次只发一次；失败的标记不重试（本次会话） |
| 6 | **后端协程** | `http.ServeFile` 天然异步；超大文件（>50MB）原图需显式点开 |
| 7 | **数据分页** | 列表后端分页（每页 ~200 行），前端只持当前页 + 总数 |
| 8 | **进度节流** | 扫描进度 ≥100ms 或每 1000 文件 emit 一次 |
| 9 | **UI 线程零 I/O** | 全部文件操作在 goroutine；事件只传轻量对象 |
| 10 | **内存上限** | 前端不持有文件内容；后端索引仅元数据（~14 万条 ≈ 数十 MB，可控） |

### 4.4 预览面板布局（右栏）

```
┌ 预览面板 ────────────────────────┐
│ [←] [→]  上一张/下一张（连续浏览）│
│ ┌─────────────────────────────┐ │
│ │  媒体区（图片自适应 / 视频   │ │
│ │  播放器 / 元数据卡片）       │ │
│ └─────────────────────────────┘ │
│ 详情：路径 / 大小 / mtime / 文件ID / 内容哈希│
│       说明（reason 标签，悬浮释义）/ 关联情况│
│ [在文件夹中显示] [同内容 N 份 · 勾选副本/勾选全部] │
└─────────────────────────────────┘
```
- **连续预览**：选中一行后，方向键/按钮可在**当前筛选结果集**内前后切换，预览始终秒开
- **在文件夹中显示**：定位文件真实路径（`open -R` / `explorer /select`）——仅展示不操作
- **内容哈希**：完整 64 位显示（等宽字体，可选中复制到筛选表达式）；大小唯一
  未计算时显示「未计算（大小唯一）」；已计算但内容组只有自己时标注
  「同大小但内容不同」（哈希计算按大小冲突组触发，同大小 ≠ 同内容）
- **同内容 N 份按钮 = 勾选模式切换**：默认「勾选副本」（保留一份不勾）→
  点击后切为「勾选全部」（含保留份）→ 再点切回，反复点击来回切换

## 5. 各功能区详细说明

### ① 顶栏
- 数据根：自动探测结果显示 + 可改（校验存在性）
- 账号下拉：`QQ 10001（最近）` / `QQ 10002` / `unknown（按时间排序）`
- [扫描]/[停止]：扫描在 goroutine，进度条节流更新；扫描中禁止 [清理]
- 底部 toast 提示（扫描完成/勾选反馈等）~6s 自动消失，重新扫描会先清掉旧提示

### ② 左栏（类型/月份树）
- 类型节点：Pic / Video / Ptt / Emoji / File / dataline（勾选 = 扫描/显示范围）
- 月份节点：`2021-04` … `2026-08`（按账号 Pic 实际存在列出，可折叠）
- 点月份 = 过滤该月；显示各节点文件数与大小（扫描后填充）

### ③ 中栏（文件浏览工作区）
- 虚拟化表格，列：`[☑] 缩略图 | 名称（文件ID = QQ 原文件名 md5）| 类型 | 大小 | 修改时间 | 说明`
- 排序（点击列头）：大小 / 时间；筛选由命名筛选器（条件表达式）承担
- reason 标签：短标签 + 悬浮 tooltip 解释含义（见 03 §4）
- 勾选列：默认不勾选；勾选实时反馈到底栏

### ③b 去重建议（工具栏「去重建议」按钮 → 对话框）
- **分组依据 = 内容哈希（SHA-256）**，不是文件名 md5：QQ 只按目录去重，
  字节级相同的文件在不同目录/月份/账号下名字可能完全不同
- **单一交集语义**：全索引分组（保留一份全局副本，原图优先、其次 mtime
  最新）；**可去重项 = 组内副本 ∩ 当前筛选**。面板不写说明段——行结构
  自明：每行 = 一组 → 「保留 1 份：…」（保留份在筛选外时行内标「筛选外」）
  → 「可删 M 份」→ 按钮。勾选按钮带即时状态（已勾选 ✓）+ toast，保留项
  被勾选时行内标记 ⚠
- **域内重置语义**：去重建议是另一种筛选器——应用建议时其作用域内（该
  内容组/全部展示组）的勾选状态以建议为准（副本勾选、保留份取消勾选），
  **域外文件不受影响**；它不监管筛选器之外的勾选操作，也无需删除端的
  最后副本防线。预览面板「勾选副本/勾选全部」同样以当前筛选+作用域为界
  （不跨筛选勾选）
- 操作：逐组「勾选此组副本」或「全选全部多余副本」→ 底栏清理流程（备份/审计不变）
- **关联入口**：预览面板「同内容 N 份 · 勾选副本/勾选全部」（模式切换，见
  §4.4）按该行的内容哈希直接圈定整组副本并勾选；`contentHash` 是筛选表达式
  字段（`contentHash ~ <前缀>` 可前缀筛选），`| select(dup)` 管道可把任意
  筛选结果展开为其内容组（docs/04 §3）
- 大小唯一的文件不计算哈希、永不入组（同内容 ⇒ 同大小，无孪生可能）；
  同大小但内容不同的文件会**计算哈希但不入组**（组内仅自己一份）
- **筛选器（命名筛选）**：工具栏 = 置顶筛选器（按列表顺序），「更多」= 未置顶。
  内置筛选器仅首次启动作为种子写入用户筛选器列表，此后与自定义筛选器
  **完全同权**（可重排/修改/置顶/删除；删除即永久删除，不再由内置代码恢复）

### ③c 筛选器编辑器（「⚙ 编辑」对话框）
- 双视图：**列表（简易）** = 条件行 + 嵌套且/或组；**表达式（高级）** =
  文本语法（docs/04 §3），两边同源，切视图即同步当前筛选的规范文本
- 表达式视图内嵌**可折叠「语法帮助」面板**（默认收起，避免常驻占位）：
  完整列出操作符语义（`~` = 子串包含 LIKE %值%；`in` 括号列表）、全部字段
  与取值（biz/sub 的枚举、month 格式、contentHash 前缀匹配等）、管道函数
  （select/order/take/drop，按书写顺序执行）与示例
- 表达式解析错误就地显示（红色），指向具体记号与修正方式；验证通过才可应用

### ④ 右栏（预览面板，见 §4.4）

### ⑤ 底栏（统计与操作）
- 统计：当前筛选的文件数与总大小（`1.4 万个文件 · 44.0G`）
- **可释放总量**：随勾选实时累加（`已勾选 5.2G`）——字节在 App 层**精确
  累计**（勾选行带 size、全选 = 筛选总量、去重组按逐份大小增量），绝不
  依赖虚拟列表已加载行（全选/去重等大批量勾选会跨出已加载页）
- [清理] 按钮：无勾选时 disabled → 点击弹出**清理确认对话框**（两个显式
  opt-in：☐ 生成审计记录（默认关）、☐ 以移动代替删除（默认关；未设备份
  目录时禁用确认并引导「去设置」））→ **Go 侧原生对话框最终确认**（列出
  数量/大小/处理方式/审计选择）→ 执行
- **清理结果对话框**：清理完成后自动弹出，统计（处理/移动/删除/跳过/失败/
  释放）+ **跳过/失败**逐文件明细（十万级文件的完整清单过长，不再全量
  回显），并自动重新扫描；审计报告（勾选后系统 tmp 下带时间戳的 JSONL，
  后端自动打开供查看/另存）是完整的权威清单

### ⑥ 设置对话框（菜单/齿轮进入）
- 主题（跟随系统/浅色/深色）、备份目录（`--backup-dir`，默认仅审计日志）
- **高级**：三个 opt-in 门控（与 CLI config 的 clean_* 共用一份）——
  传输缓存（dataline/.tmp NFC 残留）、运行日志、头像缓存，默认**不勾选**
  （扫描与清理都不覆盖）；勾选保存后自动重新扫描生效。普通类别门控
  已随分级模型一起移除：GUI 下选择权完全在筛选器

## 6. 数据模型（前后端契约）

```go
// 前端只拿这些轻量对象
type FileRow struct {          // 中栏一行
    ID       int    `json:"id"`        // 后端索引行号
    MD5      string `json:"md5"`       // 文件ID：QQ 取自原文件名的 md5（标识，非内容）
    Biz      string `json:"biz"`       // pic/video/...
    Sub      string `json:"sub"`       // Ori/Thumb/...
    Month    string `json:"month"`
    Size     int64  `json:"size"`
    MTime    int64  `json:"mtime"`
    Reason   string `json:"reason"`    // reason 标签（展示说明，悬浮释义）
    ThumbURL string `json:"thumbUrl"`  // /preview/... 或 ""
    OriURL   string `json:"oriUrl"`    // /preview/... 或 ""
    ContentHash    string `json:"contentHash"`    // SHA-256；仅同大小冲突组计算
    ContentDupCount int  `json:"contentDupCount"` // 字节级相同副本总数（含自身）
}

// 分页查询：后端按筛选条件返回一页 + 总数
func (b *Backend) QueryRows(req PageQuery) (PageResult, error)

// 统计：当前筛选范围的分档汇总（勾选后前端本地累加）

```

## 7. 性能预算（验收标准）

| 指标 | 目标 |
|---|---|
| 扫描 14 万文件 | < 15s（并发，进度可见，可停止） |
| 内容哈希二次扫描 | 仅读大小冲突组（同内容 ⇒ 同大小）；8 路并发，进度可见，可停止 |
| 列表滚动 | 60fps（虚拟化，14 万行不卡） |
| 缩略图预览 | 缓存命中 <100ms；首次 <500ms |
| 连续浏览切换 | <100ms |
| 前端内存 | <100MB（不持有文件内容） |
| 扫描/预览同时进行 | 互不阻塞（独立通道） |

## 8. 实现顺序建议

1. 后端：discovery + classify + rules（纯逻辑，先 CLI 可测）
2. 后端：分页查询 + 统计接口
3. 前端：顶栏 + 扫描 + 中栏虚拟化表格（**先实现虚拟化与分页，验证 14 万行流畅**）
4. 前端：左栏树 + 筛选排序
5. 预览：AssetsHandler + 右栏预览面板（**懒加载 + 缓存 + 并发限制**）
6. 清理流程：勾选 → 确认 → 执行 → 审计
7. 设置对话框 + 打磨
